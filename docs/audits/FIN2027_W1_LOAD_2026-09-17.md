## Finding · loader writes invented zeros on budget-only cells (P0-class, log-only per Kevin ruling 2026-09-17)

### The behaviour

Both `scripts/derive_pnl_actuals.mjs` and `scripts/load_pnl_history.mjs` handle absence like this:

```
if (actual == null && budget == null) -> skip row (no pnl_actuals row written)
else                                  -> write row with:
                                         actual = (actual == null ? 0 : round2(actual))
                                         budget = (budget == null ? null : round2(budget))
```

A workbook cell where the actual side is blank AND the budget side is populated ends up as a `pnl_actuals` row with `actual = 0`, `budget = <workbook budget>`. Because `pnl_actuals.actual` is `NOT NULL` (per `pnl-1-actuals-and-status.sql:126`), a row with `actual = 0` cannot be distinguished from a row where the workbook explicitly reported zero spend.

### The contract text this contradicts

From `docs/migrations/pnl-1-actuals-and-status.sql` header, BINDING:

> "An ABSENT `(account_key, fiscal_year, period_no, line_code)` row means NOT REPORTED, never $0. The `actual` column is NOT NULL, so absence is the only channel the workbook has for 'no figure this period'. A row explicitly loaded with actual=0 DOES mean zero."

The absence-contract has ONE channel: no row at all. The loader currently writes a present-with-zero row for `actual = null, budget = non-null`, which the contract's second sentence explicitly forbids by design.

### Counts across the three loaded years

- **FY2024 P1..P13**: 1,110 present-with-zero-actual cells across all 9 portfolio accounts (~30% of the 3,708 loaded FY2024 rows).
- **FY2025 P1..P13**: 88 present-with-zero-actual cells; heaviest on CIN - KY P13 (24 lines) and CIN - OH scattered late-year (~38 cells).
- **FY2026 P1..P9**: **839 present-with-zero-actual cells** (~26% of the 3,167 currently on the LIVE KPI board).

Grand total across three years: **2,037 rows** in `pnl_actuals` where `actual = 0` was written by the loader but the workbook made no claim of zero spend.

### Where the finding lives in the loaders

`scripts/derive_pnl_actuals.mjs` (via the shared core module `scripts/lib/pnl_load_core.mjs`) - the FY2026 loader that populates the LIVE KPI board.
`scripts/load_pnl_history.mjs` - the new FY2024/FY2025 historical loader.

Both share the same `actual = actual == null ? 0 : round2(actual)` semantics.

### Disposition per Kevin ruling 2026-09-17

Not fixed in W1. The fix is a design decision (discard the budget value, or make `pnl_actuals.actual` nullable on a live table) plus a KPI-lane change (readers must be updated to distinguish absence from zero). Backlog doc opened: `docs/backlog/pnl-actuals-invented-zeros.md`.

## Pass-through-food accounts (CIN - OH, STL - MO, STL - FL)

CIN - OH, STL - MO and STL - FL bill food to the client as a pass-through reimbursement. These accounts carry no food cost by design, so $0 on `3200.1` is the correct value, not a missing one. The `1374.x` / `1385.x` reimbursement codes do not appear in these tabs because reimbursable revenue and cost never reach the fee P&L.

W4 design constraint: cost-per-meal metrics must exclude these three pass-through accounts from BOTH the numerator (food cost) and the denominator (meal count). Their meal counts paired with $0 food cost would drag a portfolio-blended figure artificially low.

Probe evidence: `scripts/_probe_fin2027_q1q2_reroute_and_absence_semantics.mjs` (Q1 pass) scanned rows 1..250 of every reroute-account portfolio tab in both FY2024 and FY2025 workbooks; found zero occurrences of 1374 or 1385 code families. The only off-catalog codes in these tabs are 12 dotless group headers (2400, 3100, 3200, 3400, 3500, 5002, 5004, 5006, 5012, 5013, 5016, 5017), all blank at cell level.
