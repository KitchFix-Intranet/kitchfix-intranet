## Things learned today

1. **The opsNotify pattern was actually pervasive.** Audit #1 said "no SA-auth concern in this file" because no JWT was hand-rolled. Technically correct. But the local `opsNotify(token, ...)` was a wrapper that hid user-OAuth writes behind a service-name. PR #43 caught it for notifications. Audit #3 then caught 3 MORE user-OAuth writes for the actual data (labor_plans, labor_sold_revenue, deep_clean_days). **Pattern to watch in future audits: local helpers that shadow canonical lib exports are a red flag, especially when they take a `token` parameter the canonical version doesn't.**

2. **The streak bug had been latent for as long as the feature existed.** It only manifests if a chef submits homestands out of order. Since most chefs submit in order, the bug never surfaced in real usage - but the math was wrong from day one. **Reminder: working software is not the same as correct software.** Audits catch the second.

3. **BUSINESS_NOTES.md is paying off big.** The TXR-V revenue-flex math entry alone is worth the audit's time investment. Without it, the migration would either re-derive it wrong or strip it entirely as "weird code that probably doesn't matter." Now it's preserved.

4. **Recon-before-audit prevents bundle mis-scoping.** The Audit #4+#5 bundle recon (read of invoiceActions.js structure) revealed the bundle is bigger than originally framed. Catching this now saves a mid-PR "uh oh" later.

5. **Claude Code's recon gates work as designed.** Twice today (homestand id format check, scope-mismatch on the SUPABASE_MIGRATION.md backlog list), CC paused for human input rather than guessing. The friction is the feature.
