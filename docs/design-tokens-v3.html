KitchFix Design Tokens

v3 - the foundation. Built to the standard the audit holds: perceptual color (OKLCH-generated ramps), accessibility from token zero (every text pair computed against WCAG AA), full category coverage, and an icon contract - on top of the v2 two-tier architecture. The two live toggles (density, dark) prove the system re-themes by remapping the semantic layer alone.

What the audit changed (v2 -> v3)

  • Color is now generated, not eyeballed. Every ramp built in OKLCH at fixed perceptual-lightness steps - even visual weight, predictable contrast.
  • Accessibility is constructed. Every status text color is the computed darkest step that passes AA on its fill (see the Contrast Report). The amber accent fails white-text AA at 3.19, so the system routes around it - --accent-solid (amber-600, 4.90) is the white-text path.
  • Five missing token categories added: motion (duration + easing), focus-ring, border-width, z-index, opacity - plus reduced-motion wired at the token layer.
  • Typography is a modular scale (1.2 ratio) with roles that lock size + weight + leading + tracking, and a mandated tabular numeric role.
  • Icons are a real pillar: one family (Lucide), size tokens, currentColor, and a concept->glyph map.
  • Dark mode proven as a semantic-only remap - toggle it below.

The model

Two tiers, one rule

Components reference semantic tokens, never primitives. Change a primitive and the system shifts coherently; remap a semantic alias and you re-skin (dark / dense / rebrand) with zero component edits.
