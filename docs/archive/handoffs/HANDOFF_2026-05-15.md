## Things learned today (rough edges exposed)

1. **Claude Code path-resolution bug.** When Bash tool calls modify files in place (e.g. `sed -i`), the harness's permission UI sometimes intercepts them and surfaces as an Edit-style prompt with a wrong path - specifically `../../docs/<filename>` that resolves to a non-existent location and gets reported as "File does not exist." Confirmed via `pwd` mid-session that my shell CWD was correct at `/Users/kevinfietek/dev/kitchfix-intranet`; the path mismatch was harness-side, not shell-side. Workaround used today: Kevin ran the bulk `sed` from his own terminal directly, then I picked up at the diff/commit/PR steps. Unclear if this is reproducible or session-specific. Worth filing if it recurs.

2. **"Quick win" estimates near auth-adjacent code are systematically too low.** After PR #33 I gave the e2e CI fix a "~30 min" estimate based on swapping `PLAYWRIGHT_BASE_URL`. Task 3 research today revealed that cookie domain scoping (NextAuth defaults to host-only cookies) means the swap-alone fix would replace occasional prod flakes with every-PR auth failures. Real fix needs an auth.js change. **Default for future estimates: if a "fix" touches anything auth-adjacent, assume "needs careful scoping" not "quick win" until proven otherwise.**

3. **NextAuth default cookies are host-only, not domain-scoped.** Cached auth state from `kitchfix-intranet.vercel.app` does not apply to `kitchfix-intranet-<hash>-<team>.vercel.app`. This is what makes "just point Playwright at the preview URL" not actually work. Solution path documented in PR #38; deferred for batching.

4. **Em-dash population is bigger than expected.** Total: 1,179 across 133 files. Today's sweep handled 458 in canonical docs (excluding HANDOFF and source). Source code has its own complications - `'—'` is used as a deliberate "no value" UI placeholder character in vendor lists, calendars, incident details, etc. (about 30-50 instances). Replacing those would change visual design. Source code sweep needs at least 2 follow-up PRs (comments and user-facing strings, with placeholders preserved).

5. **`SLACK_RECAP_WEBHOOK` is not analytics-related** despite the name. It's used by `/api/cron/backup-sheets/route.js:54` directly via `process.env`, not through the (now-stubbed) analytics library. My PR-3 plan initially mis-attributed it. Verified by grep before stubbing analytics.js - env var preserved, `slackRecap` function in the stub-target lib deleted with the rest of the dead lib.
